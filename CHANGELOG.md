# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [semver](https://semver.org/lang/ru/).

До `1.0.0` минорная версия может нести ломающие изменения публичного API; правило подключения
«Up to Next Minor» на этот период надёжнее, чем «Up to Next Major».

## [0.2.1] — 2026-08-23

### Исправлено
- Протягивание переписки вниз убирает клавиатуру (`scrollDismissesKeyboard`, iOS 16+).
  Раньше выйти из ввода было нечем: своей кнопки «Готово» у поля нет, а хост-приложение
  обычно показывает чат без навигационной панели — у человека оставался единственный
  выход, кнопка закрытия, которая уводит из чата целиком. На iOS 15 поведение прежнее.

## [0.2.0] — 2026-08-15

Переход на собственный канал платформы (`mobile_app`). **Ломающая версия:** интеграция 0.1.x
не заработает без правок — см. «Миграция» в README.

### Изменено (ломающее)
- Чат переехал с `/api/v1/widget/*` на `/api/v1/mobile/*`: `register` (он же открытие сессии) →
  `chat/stream` → `messages`. JWT регистрации принимается чатом напрямую — канал заявлен
  claim'ом `ch`, а не подразумевается совпадением чисел в `aud`.
- **Один ключ вместо двух.** `configure(apiKey:baseURL:)`; параметры `pushApiKey` и `origin`
  убраны. Ключ — мобильного приложения (кабинет → Бот → Каналы → Мобильные приложения).
- **Заголовок `Origin` больше не шлётся**, разрешённые домены каналу не нужны: мобильные
  роуты его не проверяют. Требование вписывать `https://<bundleId>` в кабинет отпадает.
- `conversationId` больше не уходит в запрос: тред резолвит сервер по паре
  (приложение, устройство). Наружу приходит событием `meta` — по-прежнему только чтобы
  приложение подавило свой же пуш; пространство id **сменилось** (значения 0.1.x не годятся).
- `setPushToken(_:)` **не отправляет токен в MeerBot**, а сохраняет его в
  `MeerBot.shared.pushToken`. Пуш «менеджер ответил» шлёт бэкенд интегратора, которого
  платформа уведомляет вебхуком и который адресует по `external_user_id`. Причина: в
  регистрации `deviceToken` — ключ уникальности устройства, от него зависит тред; ротация
  APNs-токена заводила бы новый диалог с пустой историей, а до выдачи разрешения на
  уведомления чат был бы недоступен вовсе. SDK шлёт стабильный идентификатор установки.
- `APIClient.history()` возвращает `HistoryPage` (сообщения + `hasMore` + `mode`) вместо
  массива; `WidgetSession` заменён на `MobileSession`, `registerDevice(apnsToken:)` удалён.
- Приветствие над пустой лентой задаёт приложение (`store.setGreeting`): у канала нет
  серверного источника — `ClientMobileApp` не хранит ни названия чата, ни приветствия.
- `reset()` меняет идентификатор установки, то есть заводит НОВЫЙ тред: прежняя переписка
  остаётся за прежним устройством.

### Добавлено
- `MeerBot.shared.refresh()` — привести ленту к серверной, не открывая новый диалог и не
  перерегистрируя устройство: приложение вернулось на передний план либо его бэкенд разбудил
  его пушем «менеджер ответил». Паритет с Android; в отличие от `handlePush(_:)` работает и
  когда пуш пришёл без `conversationId` (у канала он не обязателен — тред один на устройство).
- **Автор сообщения переживает перезапуск приложения.** `HistoryMessage` получил `authorKind`
  (`ai` | `manager`) и `authorName`; лента подписывает ответ менеджера человеком не только в
  потоке, но и после догона истории. Раньше подпись жила до сворачивания приложения — то есть
  в сценарии «менеджер ответил → пуш → пользователь вернулся» её не было никогда. Поля
  отсутствуют у платформы старше 23.08.2026 → автор считается ботом, как и раньше.
- `MeerBot.shared.identify(token:)` и `identityStatus()` — verified identity. Токен уходит в
  регистрацию, статус проверки читается из ответа. Провал мягкий: сессия живёт анонимно, но
  причина видна (`rejected` · `stale` · `not_configured`), а не теряется в наших логах.
  Приложение с включённым «требовать идентификацию» без него получает `403 identity_required`.
- `ChatController.conversationId` — read-only и `@Published`. Нужен приложению хоста, чтобы
  **не показывать пуш о диалоге, открытом на экране прямо сейчас**: раньше значение жило
  внутри `APIClient`. Заполняется событием `meta` и `openConversation` (регистрация про
  диалог ничего не сообщает).
- Отказы канала объясняются пользователю по своим кодам: `identity_required`,
  `mobile_app_inactive`, `assistant_disabled`, `daily_budget_exceeded`,
  `conversation_cap_reached`, `rate_limited`, `platform_mismatch`.
- Режим треда применяется из `GET /messages` даже при пустой ленте: «диалог у менеджера» —
  состояние треда, и без этого экран предлагал бы писать боту, который в этом режиме молчит.

### Исправлено
- `channel_mismatch` больше не вызывает бессмысленный повтор запроса: токен не протух, он от
  другого канала (403), и перевыпуск его не исправит.

### Границы
- Вложения, App Attest и cert pinning по-прежнему не реализованы.
- Эскалация в инбокс каналом пользователю не обещается: события `escalation` он не шлёт.
- История диалогов из 0.1.x не переезжает — она осталась в веб-канале.

## [0.1.0] — 2026-08-11

Первая работоспособная версия: чат со стримингом, восстановление после обрыва, регистрация пуш-токена.

### Добавлено
- `MeerBot.shared.configure(apiKey:pushApiKey:origin:baseURL:)` — настройка SDK.
- `MeerBot.shared.chatView(title:primaryColor:onClose:)` — готовый SwiftUI-экран чата.
- `MeerBot.shared.chatController()` — доступ к состоянию для собственного UI.
- `MeerBot.shared.preconnect()` — прогрев сессии перед показом экрана.
- `setPushToken(_:)` / `handlePush(_:)` — регистрация APNs-токена и переход в диалог из пуша.
- Потоковый разбор SSE, обновление 15-минутного JWT с одним повтором, догон истории после обрыва.
- 40 тестов: разбор SSE, обновление токена, поведение при обрыве сети, форма запросов.

### Исправлено
- Пакет не собирался вовсе: тест-таргет был объявлен без каталога `Tests/`.
- `TextField(axis:)` требует iOS 16 при заявленном минимуме iOS 15 — добавлена ветка для iOS 15.
- Разбор SSE терял текст, если UTF-8 символ разрывался границей сетевого чанка (кириллица — 2 байта).
- Тело запроса чата отправлялось полем `content`; бэкенд принимает `message`.
- `chatView()` возвращал заглушку вместо реального экрана; `ChatView` отвечал фиксированной строкой.
- `setPushToken` / `handlePush` печатали в консоль вместо работы с API.

### Известные ограничения
- Чат работает по ключу headless-виджета, пуши — по ключу мобильного приложения (два ключа).
- Доставка пушей на бэкенде — заглушка; аттестация устройства не реализована.
- Нет вложений и verified identity.
